# Band Secret Vote — 결정 기록

## ADR-001 — 추천자별 비밀투표 구조
- **상태: Accepted (2026-11-10)**
- **결정**: 6명이 각자 3곡 제출하고 각 투표자는 추천자별 3곡에서 1곡을 선택한다. 본인 추천 그룹에도 투표할 수 있다.
- **근거**: 추천자 6명에게 각각 한 곡의 최종 후보권을 보장한다.
- **영향**: 전원 참여 시 36개 선택이며 최종 6개 그룹의 1위곡을 결과로 표시한다.

## ADR-002 — 공개 페이지와 개인 URL 분리
- **상태: Accepted (2026-11-10)**
- **결정**: 일반 URL에 후보 18곡, YouTube 링크, 시작·마감 일정, 기간 중 완료 인원 진행률, 결과 공개 가능 시 결과를 보여준다. 6개의 개인 URL은 기간 중 투표 화면으로 진입한다.
- **영향**: 공개 페이지에 개인 URL은 표시하지 않는다. **선택 데이터는 공개 조건 충족 전에는 비공개**, 충족 후에는 최종 선택과 투표자 이름을 연결하여 공개한다.

## ADR-003 — 투표 기간 중 변경 허용
- **상태: Accepted (2026-11-10)**
- **결정**: 마감 전에는 개인 URL로 언제든 재접속 및 투표 수정 가능. 마지막으로 성공적으로 제출된 **완성형 6개 선택**만 유효하다.
- **영향**: 수정 횟수와 관계없이 참여자는 한 명으로 집계한다. 마감 시각 이후 수정 요청은 거부한다.

## ADR-004 — 결과 공개 이중 조건
- **상태: Accepted (2026-11-10)**
- **결정**: 서버 기준 `now >= end_at` **그리고** `submitted_members == 6`을 동시에 만족할 때만 득표 집계·최종 결과·개인별 최종 선택을 공개한다.
- **영향**: 투표 진행 중 또는 마감 후 미참여자가 있으면 개인 선택·중간 집계를 보여주지 않는다.
- **주의**: 마감 후 5/6인 경우 보류 상태가 지속된다. 기간 연장이나 재개는 미결정 정책이다.

## ADR-005 — 공개 웹사이트 호스팅 및 배포 저장소
- **상태: Accepted (2026-11-10)**
- **결정**: 
  - 사용자에게 공개할 웹사이트는 **GitHub Pages**로 호스팅한다.
  - 전용 배포 저장소: `https://github.com/BongCheolShin/band-secret-vote.git`
  - 배포 사이트 URL: `https://BongCheolShin.github.io/band-secret-vote/`
  - GitHub Pages 빌드 및 배포는 GitHub Actions 워크플로를 통해 자동으로 수행한다.
- **제약**: Pages는 정적 프론트 배포. 영속 저장·투표 인증·집계 공개 판정은 Supabase DB/API로 분리한다. (ADR-007)

## ADR-006 — 투표 중 비공개, 결과 발표 후 실명별 최종 선택 공개
- **상태: Accepted (2026-11-10)**
- **결정**: 투표 중에는 타인의 선택·중간 득표를 비공개로 한다. 발표 조건(마감 경과 AND 6명 전원 제출)을 만족하면 **일반 공개 URL**에서 6명 각각의 이름, 추천자 6개 그룹에서 최종 선택한 곡(총 36건), 그룹별 득표와 선정 결과를 공개한다.
- **범위**: 투표 기간 중 변경 가능한 정책은 그대로 유지한다. 결과 발표는 마감 시점에 유효한 **최종 제출**만 대상으로 하며 변경 과정/과거 선택 이력은 공개하지 않는다.
- **공정성**: 공개 결과의 선택 내역과 그룹별 득표가 일치해야 한다. 모든 유효 투표가 6그룹을 채워 그룹별 6표, 총 36표가 되어야 한다.
- **고지**: 투표 제출 전 개인별 최종 선택이 추후 실명으로 **모든 일반 URL 방문자에게 공개**됨을 분명히 안내한다. 이를 영구 익명투표라고 표현하지 않는다.
- **위험과 제약**: 공개 URL을 아는 제3자도 이름과 선택을 볼 수 있다. 팀원만 결과를 보게 하는 별도 접근 제한은 현재 확정 범위가 아니며 향후 요구 시 추가 논의한다.

## ADR-007 — 기술 스택 및 데이터베이스 아키텍처
- **상태: Accepted (2026-11-10)**
- **결정**: 
  - **프론트엔드**: React + Vite + TypeScript + Tailwind CSS, GitHub Actions를 통한 GitHub Pages 배포.
  - **백엔드/DB**: **Supabase (PostgreSQL + RLS / Edge Functions)** 무료 티어 활용.
- **근거**: GitHub Pages는 정적 호스팅이므로 투표 데이터 저장 및 '마감 전 중간 집계 은닉(비밀투표)'을 서버 레벨에서 안전하게 보장하기 위해 서버리스 DB 연동이 필수적임. 6명 규모의 투표 트래픽은 무료 티어로 완전히 커버 가능하며 즉각적인 응답성을 제공함.
- **영향**:
  - 클라이언트 브라우저는 Supabase 익명 키(Anon Key)로 통신하되, RLS 및 Postgres 함수(RPC)로 마감 전 중간 결과 열람을 차단함.
  - 비밀 서비스 롤 키(Service Role Key)는 절대 프론트 번들에 포함하지 않음.

## ADR-008 — 고엔트로피 난수 투표 토큰 정책
- **상태: Accepted (2026-11-10)**
- **결정**: 
  - 개인별 URL 토큰에 멤버의 이니셜(sh, sk 등), 번호, 힌트성 문자열을 일절 포함하지 않는다.
  - 암호학적으로 안전한 32자리 16진수 난수(Cryptographically Secure Random Token)를 생성하여 발급한다.
- **근거**: 이니셜이나 순번이 포함되면 다른 멤버의 투표 URL을 쉽게 유추(Brute-force/Guessing)하여 타인의 투표를 변조하거나 사전 열람할 위험이 발생하므로 이를 원천 차단한다.
- **영향**: 무작위 대입 공격이 수학적으로 불가능해지며, 본인의 개인 URL은 오직 카카오톡 1:1 대화로 전달받은 링크를 통해서만 접속 가능함.

## ADR-009 — 추천 그룹 내 최다 득표 동점 처리 정책 (사용자 확정)
- **상태: Accepted (2026-11-10, 사용자 확정)**
- **결정**: 
  - 특정 추천자 그룹 내에서 1위 곡이 복수로 동점(예: 3표 vs 3표)일 경우, **해당 그룹의 추천인(본인)이 직접 투표한 곡을 최종 선정곡으로 자동 확정**한다.
  - 상단 선정곡 카드에 `[추천인 동점 우선]` 뱃지를 부여하여 선정 근거를 투명하게 공개한다.
  - 만약 추천인이 투표한 곡이 1위 동점 후보군에 없는 극히 예외적인 경우에 한해서만 공동 1위 후보들을 묶어 `[협의 / 결선 필요]` 카드로 표기한다.
- **근거**: 추천자 그룹별 곡 선정의 공정성과 주체성을 살려 추천자 본인의 선호도를 동점 해결의 최우선 기준으로 채택함.

## ADR-010 — 모바일 가독성 및 폰트 크기/핀치 줌 최적화
- **상태: Accepted (2026-11-10, 사용자 피드백 반영)**
- **결정**:
  - 모바일 브라우저의 핀치 줌(두 손가락 화면 확대) 제한(`user-scalable=no, maximum-scale=1.0`)을 전면 해제하여 사용자가 자유롭게 화면을 확대할 수 있도록 보장.
  - 곡 제목, 가수명, 안내문, 버튼, 라디오 박스의 기본 폰트 단위를 한 단계씩 상향(`text-sm` → `text-base` ~ `text-lg`, `text-xs` → `text-sm` ~ `text-base`).
  - 루트 rem 기준 폰트 크기 및 모바일 레이아웃 너비(`max-w-md` → `max-w-xl`)를 확장하여 시원한 여백과 가독성을 확보.
- **근거**: 실제 스마트폰(카카오톡 인앱 브라우저 등) 화면에서 곡 제목 및 안내문구가 작게 느껴지는 문제 해결.

## 검토 중 (미확정)
- **관리자 권한**: 별도 인증 및 투표 시작 후 후보 변경 제한.
- **동점 처리**: 동점 그룹 결선 재투표 방안 검토.
- **후보 중복**: 동일 곡의 다중 추천을 허용할지 미결정.
- **미참여 마감**: 운영자가 시간을 연장·재개할지, 기한에 따라 투표를 다시 시작할지 미결정.
- **사전 비공개 강화**: 결과 공개 전 DB 최고 관리자의 사전 열람을 암호화로 차단할지 정책 미결정. 결과 공개 후에는 실명별 최종 선택을 의도적으로 공개한다.
- **발표 UX**: 자동 갱신·결과 발표 애니메이션은 제안 상태.

## 변경 원칙
사용자 확정 전에는 검토 사항을 'Accepted'로 승격하지 않는다. 주요 정책 변경은 본 문서와 `v0.1/spec.md`를 동기화한다.
