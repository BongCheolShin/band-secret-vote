# Band Secret Vote v0.1 — 기능 요구사항

## 1. 목표 및 범위
- 대상: 밴드 팀원 6명, 추천자당 3곡, 총 18개 추천 엔트리.
- 목표: **추천자별 3곡 중 한 곡씩**, 총 6곡을 최종 선정한다.
- 공개 웹사이트: GitHub Pages. 모바일 브라우저 우선, 데스크톱에서도 동작.
- 계정 없이 투표 가능한 개인별 링크를 카카오톡 개인 대화로 전달하는 운영 흐름.
- 공개 사이트에서 공연곡 추천 목록과 YouTube 링크를 함께 열람 가능.
- 이번 문서에서 특정 공연명, 실곡, 날짜, 실제 개인 URL은 지정하지 않는다.
- **비밀투표의 정의**: 투표 진행 중에는 **타인의 선택과 중간 득표가 비공개**다. 영구 익명이 아니다. 결과 공개 조건이 충족되면 일반 URL 방문자 모두에게 6명 각각의 **이름과 최종 선택 내역**을 공개한다.

## 2. 확정 기능 요구사항
| ID | 기능 | 규칙 |
| --- | --- | --- |
| FR-001 | 후보 구성 | 6명 × 각 3곡 = 18개 추천 엔트리 |
| FR-002 | 개인 투표 | 6개 추천자 그룹마다 3곡 중 **정확히 1곡**, 총 6곡 선택 |
| FR-003 | 자기 추천곡 | 본인 추천 그룹에 대한 선택 허용 |
| FR-004 | 개인 URL | 6명 각각 별도 URL로 투표 접근, URL 미보유자는 투표 불가 |
| FR-005 | 수정 | 투표 기간 내 재방문하여 기존 선택 조회·수정·재제출 가능 |
| FR-006 | 제출 | 6개 선택이 모두 있어야 유효한 제출. 마지막 성공 제출만 집계 |
| FR-007 | 진행률 | 일반 페이지에 투표 기간 중 **완료 인원 / 6명** 공개. 개인별 선택·득표는 비공개 |
| FR-008 | 공개 페이지 | 상시 곡 목록(제목·아티스트·추천자·YouTube 링크), 일정 안내 및 상태 표시 |
| FR-009 | 시작/마감 | 서버 시각 기준 `start_at <= now < end_at`에서만 신규 제출·수정 허용 |
| FR-010 | 결과 공개 | **`now >= end_at && completed_members == 6`**에서만 득표·선정 결과·실명별 최종 선택 공개 |
| FR-011 | 미참여 | 마감 이후 6명 미완료면 결과 비공개 및 '결과 공개 대기' 상태 |
| FR-012 | 집계 | 각 추천자 그룹 내 득표 최다곡 1개를 선택. 동점 세부 정책은 미결정 |
| FR-013 | 투표 기간 비공개 | 공개 조건 충족 전 타인의 선택·그룹별 중간 득표는 일반 사용자와 운영자에게 UI/API로 공개하지 않음. 본인은 개인 URL에서 자신의 현재 선택 조회 가능 |
| FR-014 | 일정 | 공개 페이지에 투표 시작과 종료 시간을 한국시간(KST)으로 보여줌 |
| FR-015 | 운영 설정 | 투표 개설 시 6명·추천곡·일정 등록; 안전한 별도 관리자 인증 필요 |
| FR-016 | 공개 실명 내역 | 결과 공개 시 투표자 6명의 이름과 각자의 최종 6개 선택을 연결한 36개 선택 내역, 그룹별 득표수를 일반 URL에 공개. 과거 수정 내역 미공개 |
| FR-017 | 투표자 사전 고지 | 개인 URL에서 제출 전 '진행 중 비공개·결과 발표 후 이름과 최종 선택이 일반 URL에 공개됨'을 명확하게 고지 |

## 3. 공개 URL 상태
| 시점 | 공개 페이지 |
| --- | --- |
| 시작 전 | 후보 18곡, YouTube 링크, 시작/마감 일정, '투표 예정' |
| 투표 기간 중 | 위 정보 + 완료 인원 `n/6`, '투표 중'; 중간 득표 미노출 |
| 마감 후, 6명 미완료 | '결과 공개 대기', 완료 인원 표시 가능. 개인 선택/득표 비공개 |
| 마감 후, 6명 완료 | 6개 추천 그룹별 득표·선정 결과와 **6명 실명별 최종 선택(6×6 선택표)** 공개. 동점 그룹 처리 규칙 미확정 |

6명이 마감 전에 모두 제출하더라도 발표는 `end_at` 이후다. 진행률은 수정 횟수나 36개 개별 선택 수가 아닌 **완료한 사람 수**를 사용한다.

### 결과 발표 화면 상세
- 최종 선정 결과: 추천자 A~F별 후보 3곡의 득표수와 해당 그룹의 1위곡 표시(동점 처리 정책은 별도 결정).
- **투표자별 최종 선택표**: 행은 투표자 6명(실명), 열은 추천자 A~F의 6개 그룹. 각 칸에 해당 투표자가 최종 선택한 곡을 표시하여 6×6=36건 전부 공개.
- 결과 검산: 각 그룹에서 투표자별 선택을 합산하면 해당 후보 득표와 정확히 일치해야 한다. 각 추천자 그룹 총 6표, 전체 36표.
- 공개 범위: 결과 발표 후 일반 URL 방문자 누구나 확인 가능. 투표 변경/수정 이력, 링크 토큰, 관리자 정보는 공개하지 않는다.

## 4. 개인 URL 상태
| 시점 | 개인 URL |
| --- | --- |
| 시작 전 | 일정/후보 확인, 투표·수정 불가 |
| 투표 기간 중 미제출 | 추천 그룹별 1곡씩 6개 선택 후 제출 |
| 투표 기간 중 기제출 | 저장된 선택을 표시하고 언제든 수정·재제출 |
| 마감 후 | 신규 제출·수정 불가, 공개 조건 전 결과 비공개 |
| 공개 조건 충족 | 일반 URL과 동일한 결과 확인 |

기존 유효 제출을 보유한 상태에서 폼을 수정하다가 **저장하지 않고 이탈**하면 기존 제출을 유지한다. 제출 작업은 6개 선택을 트랜잭션으로 한 번에 저장/교체한다.

## 5. 상태 전이 및 불변조건
```text
SCHEDULED (now < start_at)
    ↓
OPEN (start_at <= now < end_at)  -- 기존 투표 수정 가능
    ↓
CLOSED_WAITING (now >= end_at AND completed_members < 6)
    └── 결과 비공개, 미투표자는 마감 후 투표 불가
CLOSED_READY (now >= end_at AND completed_members == 6)
    └── 결과 공개
```
- 서버 시각이 단일 기준이다. 클라이언트 시계 변경으로 우회할 수 없어야 한다.
- 투표 마감 직전 동시 수정과 중복 요청이 있어도 최종 제출은 참가자당 하나만 존재해야 한다.
- `end_at`에 도달한 이후 성공 제출은 발생하지 않아야 한다.
- 마감 후 미완료 상태의 해결 방법(기간 연장/재오픈 등)은 **미결정**이다. 결정 전 임의로 자동 결과 공개하지 않는다.

## 6. 화면·운영 인터페이스
- **공개 페이지**: 상단 제목/투표 일정/상태 → 기간 중 진행률 → 추천자별 3곡 목록/YouTube 링크 → 공개 가능 시 최종 결과.
- **개인 페이지**: 공개 후보 정보 + 추천자 그룹당 3개 라디오 선택 → 투표 중 비공개·발표 후 실명 최종 선택 공개 정책 안내 → 6개 선택 검증 → 제출/수정 완료 안내.
- **관리자 페이지**: 6명/각 3곡/YouTube 링크/투표 일정 등록, 개인별 링크 발행/재발급, 참여 숫자 확인, 기한 관리 (세부 권한 확정 전).
- YouTube 링크는 사용자가 등록한 링크를 새 창으로 열고 허용 URL 형식을 검증한다.
- 투표 기간/상태 화면은 새로고침 또는 재진입 시 서버에서 갱신한다. 자동 갱신은 UX 선택 사항.
- 접근성: 모바일 터치, 키보드 선택, 유효성 오류와 수정 성공/실패 피드백 제공.

## 7. 데이터 구조 후보 (구현 결정 전)
- `elections`: 제목, start_at, end_at, 상태 메타데이터
- `members`: 선거별 6명, 인증 토큰 해시/발급 상태
- `songs`: 선거/추천자별 3곡, 제목, 아티스트, YouTube URL
- `ballots`: 선거별 **투표자 식별자**와 최종 제출 여부/수정 시각 (결과 발표 시 실명 연결 가능해야 함)
- `ballot_choices`: 제출당 추천자 6그룹별 선택
- `admin_audit`: 후보/일정/토큰 변경 기록
- 투표자의 식별자와 현재 유효 선택의 연결은 **발표 후 실명 선택 내역을 검증 가능하게 제공**하기 위해 필요하다. 공개 전 접근 제한은 서버에서 강제한다. DB 원본 접근자에게도 사전 열람을 차단하려면 추가 암호화 정책이 필요하다.

## 8. 보안·공정성 기준
- GitHub Pages에 저장된 JS/HTML에는 개인별 URL 토큰, 관리자 인증정보, DB 특권키, 투표 원본을 포함하면 안 된다.
- 개인 투표 링크는 **비밀 자격증명**으로 취급하고 충분히 긴 난수 토큰을 사용한다. 링크 공유 시 타인 대리 투표가 가능하다는 한계를 운영자에게 안내한다.
- 서버가 모든 제출에 대해 개인 토큰 유효성, 시작/종료 시각, 그룹 개수, 선택 곡 소속, 중복/동시성 조건을 검증한다.
- **결과 공개 조건 충족 전** 공개 API는 완료 인원만 내려주며 개별 선택·중간 득표를 외부에 제공하지 않는다. 개인 URL 인증 이용자는 자신의 현재 선택만 조회할 수 있다.
- 공개 결과 API는 완료 인원이 6명이고 기한이 지났을 때에만 **실명별 최종 선택 36건, 그룹별 득표·선정 결과**를 반환한다. 관리자 UI도 기본적으로 동일한 시각 제약을 따른다.
- 발표 후 공개되는 이름/선택 내역과 투표 진행 중 비공개 정책을 개인 투표 화면에서 **첫 제출 및 수정 제출 이전에 분명히 안내**한다. 일반 URL 방문자는 누구나 발표 후 개인별 선택을 확인할 수 있음을 명시한다.
- 최종 선택의 집계와 공개 내역이 일치하도록 서버에서 단일 최종 투표 스냅샷을 기준으로 결과를 계산한다. 중간 수정 이력은 공개 결과에 포함하지 않는다.
- URL 토큰이 외부 분석·접속 로그·YouTube referrer 등에 누출되지 않도록 라우팅/Referrer-Policy/로그를 점검한다.
- 개인정보·비밀투표 무결성 검증이 완료될 때까지 실제 투표 URL을 발행하지 않는다.

## 9. 제안 기술 (미확정)
- 정적 프론트: React + Vite + TypeScript; GitHub Pages에서 빌드 산출물만 배포.
- 서버/DB: Supabase Edge Functions + PostgreSQL 후보. 비밀과 쓰기 권한은 서버 전용.
- GitHub Pages는 저장소당 하나의 사이트이므로, 기존 저장소의 Pages 사용 여부를 확인한 뒤 기존 사이트의 하위 경로 또는 **별도 전용 배포 저장소** 중 선택한다.
- 프로젝트 문서와 소스는 우선 `40-projects/band-secret-vote/`에 통합하는 Fast Track 방식을 따른다.
- GitHub Actions 배포 시 `web/dist`만 배포하고 저장소 전체와 민감 문서를 공개 아티팩트로 업로드하지 않는다.

## 10. 미결정 항목
1. 동점 시 결선 재투표 또는 사전 지정 대체 규칙.
2. 다른 추천자의 동일 곡 중복 제출 허용 여부.
3. 마감 시 5/6 등 미참여 발생 시 연장·재개 승인 주체/안내 방법.
4. 참가자 재발급·링크 분실·대리투표 대응 수준.
5. 관리자 로그인 수단, 공개 사이트 실제 저장소/도메인 및 배포 책임.
6. DB 최고 관리자도 **결과 공개 전** 선택 내역을 사전에 알 수 없도록 할 암호학적 투표 봉인 수준.

**미결정 항목은 구현 중 임의로 Accepted로 바꾸지 않는다.**
